01ÖVERSIKT


    
The Lore Weaver's Cauldron är en LLM-driven Dungeon Master. Spelaren skriver vad karaktären gör — en AI-DM narrerar utfallet, spelar NPCs och bygger världen i stunden. Men enbart en språkmodell räcker inte för ett spel: den glömmer, den hittar på, och den kan inte hålla reda på HP, guld och quests. Därför är spelet byggt kring en två-modellsprincip:


    

      KÄRNIDÉ
      
DM:n berättar. Guardian bokför. Den kreativa modellen (Qwen 3.8 Max) skriver fri narration utan mekaniska tvång. En separat mekanisk väktare (Guardian) läser narrationen i efterhand och extraherar all spellogik — skada, XP, föremål, quests, NPC-relationer — och uppdaterar det auktoritära tillståndet. DM:n behöver aldrig räkna; Guardian äger mekaniken.

Allt speldata lever i JSON-filer per kampanj — maskinläsbart, kompakt, versionshanterbart. Ingen databas. LLM:n får aldrig se rå JSON; den får en komprimerad SANNING-block istället.


    
    
02EN TURS LIVSCYKEL


    
När spelaren trycker Enter händer följande — steg för steg, i main.py:chat():


    

      
1

      

        
Guardian Pre-DM — kastdetektion <2s

        
Innan DM:n ens anropas analyserar Guardian spelarens handling + senaste DM-svar och avgör: kräver detta ett tärningskast? "Jag beställer en öl" → nej. "Jag hugger en goblin" → ja, 1d20-1 mot AC 13. Resultatet injiceras som ett råd i DM:ns systemprompt — och fungerar som fallback om DM:n glömmer [KAST:]-taggen.

      

    


    

      
2

      

        
Systemprompten monteras deterministiskt

        
_build_system_prompt() bygger varje tur ihop prompten från scratch: språk-direktiv, DM-core (v21), strids- eller narrativ-läge, SANNING-blocket, hierarkiska sammanfattningar, förra turens händelser, värld, NPCs och aktiva quests. Inget lämnas åt slumpen — se sektion 03.

      

    


    

      
3

      

        
RAG — långtidsminne injiceras Qdrant

        
Spelarens meddelande embeddas och matchas mot kampanjens faktaregister. Relevanta minnen ("värdshusvärden Borget är skyldig dig en tjänst") läggs till i systemprompten. Så DM:n kommer ihåg detaljer från 200 drag sedan.

      

    


    

      
4

      

        
DM narrerar Qwen 3.8 Max

        
Systemprompt + senaste transkript + spelarens meddelande skickas till DM-modellen. Den svarar med fri narration — och om Guardian Pre-DM begärde ett kast, en [KAST: 1d20+3 | SMIDIGHET (DC 14)]-tagg som frontend renderar som en tärningsknapp. Svaret returneras direkt till spelaren.

      

    


    

      
5

      

        
Guardian Post-DM — mekanikextraktion bakgrund

        
Efter att spelaren fått sitt svar kör Guardian i bakgrunden: den läser DM:ns narration och extraherar ALL mekanik (skada, XP, items, valuta, quests, NPCs, tid, vila, loggbok, ASCII-art, korrigeringar) som strukturerad JSON. apply_mechanics() uppdaterar state och frontend pollar fram event-kort i chatten. Spelaren väntar aldrig på detta.

      

    


    

      
6

      

        
State uppdateras & sammanfattas asynkront

        
HP, guld, inventory, NPC-relationer och quests skrivs till kampanjens JSON. Varje 20:e drag genereras en scen-sammanfattning; vid milstolpar en kapitel-sammanfattning; över hela kampanjen en kampanjbåge. Dessa matas tillbaka i nästa turs systemprompt — hierarkiskt minne.

      

    


    
Nyckelbeslutet: DM-svaret returneras direkt, Guardian körs i bakgrunden (commit 3d46e17). Tidigare fick spelaren vänta på båda — nu känns spelet snabbt medan bokföringen ändå sker.


    
    
03SYSTEMPROMPTEN — MONTERAD VARJE TUR


    
Systemprompten är inte en statisk text. Den byggs om från grunden varje tur av _build_system_prompt() (main.py:1458), i en fast ordning. Ordningen spelar roll: språk-direktivet måste komma först, SANNINGen före sammanfattningarna, osv.


    

      
1

      

        
[LANGUAGE] / [SPRÅK] — direktiv

        
Allra först. Tvingar DM att skriva ALLT på rätt språk. Överskriver svensk text i instruktionerna nedan — de är interna systemnoter, inte utdataspråk.

        
main.py:_build_system_prompt() · lang = _get_lang(state)

      

    

    

      
2

      

        
[DM-prompt v21] + DM_CORE_PROMPT

        
DM:ns identitet, ton, världskonsekvens, NPC-skapande, tärningsregler. Versionsnumret tvingar cache-miss vid ändringar. Se sektion 04.

        
models.py:173 · DM_PROMPT_VERSION = "v21"

      

    

    

      
3

      

        
Strid ELLER Narrativ — endast det som behövs

        
Finns det levande fiender i state injiceras DM_COMBAT_PROMPT (initiativ, turordning, balansguardrails per nivå). Annars DM_NARRATIVE_PROMPT. Sparar kontext i fred.

        
enemies = [n for n in state["npcs"] if relation=="fiende" and alive]

      

    

    

      
4

      

        
SANNING — auktoritärt tillstånd

        
Kompakt state (HP, guld, inventory, nivå) + pinmade fakta. Rubriken säger det rakt av: "motsäg ALDRIG detta". LLM:n får aldrig hitta på att spelaren har föremål de inte har.

        
truth_block(state) → compact_state(state) + pinned_facts

      

    

    

      
5

      

        
Hierarkiska sammanfattningar

        
2 scen-sammanfattningar + 2 kapitel + 1 kampanjbåge. Det korta minnet — se sektion 06.

        
store.load_summaries(last_n=2) · load_chapters(2) · load_campaign_arcs(1)

      

    

    

      
6

      

        
Förra turens händelser

        
Guardian Post-DM:s extraktion från förra draget ("Skada: 12, Nytt föremål: Långsvärd"). Så DM:n vet vad som faktiskt hände mekaniskt, inte bara vad den själv skrev.

        
state["meta"]["last_effects"]

      

    

    

      
7

      

        
Värld · NPCs · Quests

        
Aktuell plats, tid, väder. Upp till 10 kända NPCs (namn, roll, relation). Upp till 5 aktiva uppdrag.

        
state["world"] · state["npcs"][:10] · active quests[:5]

      

    

    

      
8

      

        
Kontextuella injektioner (vid behov)

        
Om spelaren skickade ett tärningsresultat → "TÄRNINGSRESULTAT MOTTAGET, ge utfallet direkt". Om Guardian Pre-DM begärde kast → rådet injiceras. Om ny kampanj → VAKNANDEPROTOKOLLET.

        
player_input.startswith("[Resultat:") · guardian_roll · awakening_trigger

      

    


    
Borttaget i v19: all enforcement (tag_streak, missing_roll_streak, turns_since_roll). DM:n behöver inte påminnas om mekaniska taggar längre — Guardian Pre-DM detekterar kast och Post-DM extraherar mekanik. DM-prompten bantades med 220 rader.


    
    
04DM:NS HJÄRNA — DM_CORE_PROMPT v21


    
DM:ns systemprompt (models.py:173) definierar hur DM:n berättar — men aldrig vad. Världen är fri.


    

      
DM_CORE_PROMPT — öppningen models.py:173

      

        "Du är Dungeon Master i ett D&D 5e-äventyr. Du är en kreativ, fri berättare — du väljer själv tema, ton, miljö och stämning utifrån vad spelaren vill ha och vad berättelsen kräver. Det kan vara mörkt och hotfullt, ljust och äventyrligt, mystiskt, humoristiskt, episkt — du bestämmer. Berättelsen är INTE förskriven: den formas av spelarens val, i stunden."
      

    


    
Viktiga sektioner i prompten

    

      
SektionRegel

      
Identitet & tonStandardnarration <150 ord. Längre (300–600) vid bakgrund/bok/legend. Avsluta ALLTID med en öppning. Döden är verklig. NPCs har distinkta röster.

      
Berättelsen arbetas framIngen förskriven handling, inget färdigt slut. Varje detalj spelaren ger blir en tråd. Små val får stora följder.

      
VärldskonsekvensALDRIG verkliga ortsnamn (inga "Väsby" eller "Stockholm") — påhittad fantasy-värld med egna namn. Samma plats har samma namn.

      
Mekanik → GuardianDM skriver INGA mekaniska taggar för skada/XP/items. Undantag: [KAST:] och valfria [NPC:].

      
@NPC-konversationSpelaren skriver @Namn → den NPC:n svarar direkt i sin egen röst, före DM-narration.

      
TärningskastFormat: [KAST: 1d20+MOD | ETIKETT (DC X)]. Vid mottaget resultat: ge utfallet DIREKT, jämför mot DC, nat 20 = triumf, nat 1 = katastrof.

      
Dina rollerNarratör · NPC-skådespelare · Regeldomare (VIKTIGAST) · Världsbyggare · Utmanare.

    


    
Stridsprompten (injiceras endast i strid)

    

      
DM_COMBAT_PROMPT — balansguardrails models.py

      

        Presentera fienderna → begär initiativ [KAST: 1d20+DEX | INITIATIV] → håll turordning → narrera varje runda. Och en tabell som hindrar DM:n från att döda en nivå-1-spelare med en drake:


        Nivå 1: max 7 HP, max AC 12, ALDRIG multiattack, max 1d8+2

        Nivå 2: max 11 HP, max AC 13, max 2d6+2

        Nivå 3: max 16 HP, max AC 14, multiattack endast bossar

        Nivå 4–5: max 25 HP, max AC 15, bossar får multiattack
      

    


    
Designprincip (rostad): estetiken är dark fantasy, men prompten är temafri. Castlevania/DOS/terminal-utseendet är frontend-only. DM:n får aldrig låsas till "mörk fantasy" — spelaren väljer ton.


    
    
05GUARDIAN — DEN MEKANISKA VÄKTAREN


    
guardian.py (1 257 rader) är spelets bokhållare. Två lägen, två olika modeller, två olika tidsbudgetar.


    
Pre-DM — guardian_check_roll()

    
Körs före DM-anropet, måste vara snabb (<2s). Modellen är StepFun 3.7 Flash med reasoning_effort=high. Får se spelarens handling + senaste DM-svar som kontext. Returnerar strikt JSON:


    

      
GUARDIAN_PRE_SYSTEM — utdrag guardian.py:38

      

        "Din ENDA uppgift: avgör om spelarens handling kräver ett tärningskast."


        KRÄV kast vid: attack, smygning, klättring, övertalning under press, söka dolda ting, undvika fälla, inbrott, flykt…

        KRÄV INTE kast vid: vanlig gång, normalt samtal, plocka upp saker, läsa, öppna olåst dörr, köpa/sälja, vila…

        Vid tvekan: KRÄV INTE kast. Bara faktiska risker med meningsfulla konsekvenser rättfärdigar ett slag.


        Format: {"needs_roll": true, "notation": "1d20+2", "label": "SMIDIGHET (DC 14)", "skill": "DEX"}
      

    


    
Post-DM — guardian_extract_mechanics()

    
Körs i bakgrund efter DM-svaret — latens spelar ingen roll, så här används Qwen 3.8 Max (smartare, kontextmedveten). Läser DM:ns narration + spelarens handling + de 8 senaste meddelandena och extraherar ALLT som strukturerad JSON:


    

      
GUARDIAN_POST_SYSTEM — extraktionsfält guardian.py:291

      

        Strid & hälsa: damage · healing · death

        Progression: xp (ENDAST dråp/quest/milstolpe/pussel — ALDRIG NPC-samtal) · level_up

        Föremål & valuta: items_add (med D&D-stats: damage_dice, ac_bonus, charges, magic_bonus, properties) · items_remove · currency

        Uppdrag: quests_new · quests_completed · quests_failed

        NPCs: npcs_new · npc_relations (även IMPLICITA: hjälper→allierad, attackerar→fiende) · npc_notes · npc_name_reveals

        Karaktär: character_updates (nya förmågor, bakgrund)

        Värld & tid: locations_new · time_passed · rest · new_day · day_summary

        Resurser: roll_grants (Bardic Inspiration → spawnar tärningsknapp)

        Loggbok: 1–2 meningar i dåtid, tredje person

        Stämning: ascii_art (varannan tur)

        Korrigeringar: om DM:n implikerade något som INTE borde ha hänt
      

    


    
Kritisk regel i Post-DM-prompten: "Ta ENDAST med effekter som faktiskt sker." "Du ser en bok" → INGET föremål. "Du läser boken" → INGET föremål. "Du plockar upp boken" → items_add. Detta förhindrar att DM:ns beskrivningar läcker in i inventoryt.


    
apply_mechanics() — JSON blir spellogik

    
Den extraherade JSON:en översätts till faktiska state-ändringar (guardian.py:628). Varje ändring blir ett event-kort i chatten med egen färg och SFX:

    

      🩸 skada
      ✨ läkning
      ⭐ XP
      🪙 guld
      📦 föremål
      ⚑ quest
      🎉 level-up
      📍 plats
      💀 NPC död
    


    
    
06MINNE & KONTEXT


    
En LLM drunknar om den matas hela transkriptet. The Lore Weaver's Cauldron använder en hybridmodell: State + Summary + Recent + Archive i tre nivåer:


    
KORTTIDSMINNE   ── senaste ~15 meddelanden (verbatim, naturligt flyt)
      │
SCEN-MINNE      ── var 20:e drag → 3–5 meningar (2 senaste i prompten)
      │
KAPITEL-MINNE   ── vid milstolpar → sammanfattar en hel akt (2 senaste)
      │
KAMPANJBÅGE     ── över hela spelet → den röda tråden (1 senaste)
      │
LÅNGTIDSMINNE   ── RAG + Qdrant · faktaregister · embeddas per meddelande
      │             ("Borget är skyldig dig en tjänst" → injiceras när relevant)
SANNING         ── auktoritärt state · LLM:n får ALDRIG motsäga detta


    

      
A

      

        
SANNING (truth_block)

        
Kompakt state, inte rå JSON. HP, guld, inventory, nivå + pinmade fakta. "Auktoritär — motsäg ALDRIG detta." Detta är grunden som hindrar hallucinerade föremål och felaktig HP.

      

    

    

      
B

      

        
Hierarkiska sammanfattningar

        
Scen (var 20:e drag) → Kapitel (milstolpar) → Kampanjbåge (hela spelet). Genereras av den billiga extraktionsmodellen (qwen3.6-flash), sparas som JSON med metadata, injiceras 2+2+1 i varje systemprompt.

      

    

    

      
C

      

        
RAG + faktaregister (rag.py · 448 rader)

        
Varje meddelande embeddas till Qdrant. Vid varje tur söks relevant långtidsminne fram och injiceras i systemprompten. Fakta kan också "pinnas" — då hamnar de i SANNING-blocket permanent.

      

    


    
Varför inte bara spara allt som .md? För att .md växer obegränsat — Qwen drunknar i kontext. JSON är kompakt, strukturerat, alltid aktuellt. Rullande sammanfattningar ger narrativ utan att spara varje "jag går norrut".


    
    
07TÄRNINGSCEREMONIN


    
Ett tärningskast är inte en siffra — det är en händelse. Flödet från Guardian-detektion till utfall:


    

      
🛡️GUARDIAN PREkrävs kast?

      
→

      
🐉DM NARRERAR+[KAST: 1d20+3]

      
→

      
🎲FRONTENDtärningsknapp

      
→

      
✨D20-CEREMONI3s spänning

      
→

      
📤[Resultat: 17]tillbaka till DM

      
→

      
⚖️DM GER UTFALLlyckades/misslyckades

    


    
D20-ceremonin (frontend, ~3s)

    
Fullskärmsoverlägg med en SVG-D20 (ikosahedron, guld-stroke). Fas 1 "rullar": tärningen vaggar ±12° medan en slumpad siffra flimrar — snabbt först, avtagande (delay = 50 + progress²×220ms) för att bygga spänning. Fas 2 "avslöja": tärningen landar med studs (cubic-bezier(.34,1.56,.64,1)) och resultatet tonar in.

    

      
UtfallEffekt

      
Naturlig 20Guldglöd + guldregn-partiklar + vit blixt + SFX.crit

      
Naturlig 1Blodglöd + blodpartiklar + full skärmskakning + SFX.fail

      
AnnatNeutrala guld/lila partiklar

    

    
Efter avslöjandet skickas resultatet tillbaka som [Resultat: 17]. Systemprompten injicerar då: "TÄRNINGSRESULTAT MOTTAGET — jämför mot DC/AC, ge utfallet direkt, ALDRIG fråga 'vad gör du?' först."


    
Det finns en medveten designbegränsning: ingen fristående tärningsbricka (d4–d100-knappar som rullar klient-sidan). En sådan skickar aldrig resultatet till DM:n, så kastet "händer inte riktigt". Enda tärningsvägen är DM-begärd → round-trip till LLM.


    
    
08STATE & DATA


    
Allt speldata är JSON per kampanj i backend/data/campaigns/. Guardian är den enda auktoriteten för state-ändringar — DM:n skriver aldrig direkt till state.


    
// förenklat kampanj-state
{
  "meta":        { turn_count, campaign_id, language, last_effects, last_roll_requests },
  "character":   { name, class, level, hp, max_hp, xp, ac, abilities, inventory[], currency },
  "world":       { current_location, time, weather, locations[] },
  "npcs":        [ { name, role, relation, alive, notes[] } ],
  "quests":      [ { name, description, status, reward } ],
  "pinned_facts":[ "Borget är skyldig dig en tjänst" ],
  "transcript":  [ { role, content, ts } ],        // rullande fönster
  "summaries":   { scenes[], chapters[], arcs[] }  // hierarkiskt minne
}


    
Inventory-items med D&D-stats

    
Sedan item-cards-ombygget (commit 193df16) har varje föremål riktiga D&D-stats som Guardian extraherar:

    

      damage "1d8 slashing"
      ac_bonus 16
      charges 5/7
      magic_bonus +1
      range "ranged 120"
      properties [finesse, light]
    

    
Frontend renderar dessa som klickbara kort med detaljmodal, sällsynthetsfärger (magic/rare/legendary) och equip-toggle.
