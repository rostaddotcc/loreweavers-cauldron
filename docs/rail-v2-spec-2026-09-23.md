# Rail v2 — unified header + "painting" glossary (2026-09-23)

Shared contract for the 2026-09-23 design iteration. ALL tracks read this first.

## 0. Glossary — REMOVE the word "painting"/"paint" from user-visible copy

The product feature is **image generation** (portraits/art). Never "painting", "paint",
"painted", "painter" in user-visible strings (labels, buttons, toasts, status lines,
tooltips/title=, meta descriptions, release-notes prose). **KEEP** code identifiers
(`pf-paint-*`, `advPaint*`, `pc-badge-paint`, `_runAvatarGen` etc.) and the inventory
item "War paint kit" (face paint — different meaning).

Canonical replacements (adapt grammar as needed):

| Old | New |
|---|---|
| StepFun painting / Wan 2.7 painting / premium painting | … image generation |
| painting (as turn cost: "a painting, a voice narration") | an image, a voice narration |
| premium paintings (a day/per day) | premium images |
| 1 turn per painting | 1 turn per image |
| AI-painted / painted by AI / painted portraits | AI-generated / generated by AI / AI-generated portraits |
| paint/paints/painted (verb, art) | generate/renders/generated (or "create") |
| 🎨 Paint Avatar / Paint Portrait / Paint a new portrait | 🎨 Generate Avatar / Create Portrait / Generate a new portrait |
| 🎨 Painting… / Painting ONLY your words… / Painting from your dossier… | 🎨 Generating… / Generating from your words only… / Generating from your dossier… |
| The artist is painting… | The artist is sketching… (or "Generating…") |
| Portrait painted / avatar painted | Portrait generated / avatar generated |
| Could not paint the avatar | Could not generate the avatar |
| Image provider for painting | Image provider for image generation |
| painted by the Loreweaver | portrayed by the Loreweaver |
| repaint | generate a new portrait |
| The Brushes — Image Painters / painters | The Brushes — Image Generation / the brushes |
| everyday painter / Master Painter | everyday brush / Master's Brush |

Rules:

- Every page links `rail.css?v=20260923a` **after** the `snes.css` link and loads
  `<script src="rail.js?v=20260923a"></script>` (defer or at end of body).
- **chat.html exception**: chat keeps its own inline rail CSS (source-of-truth block)
  and does NOT link rail.css (avoid double definitions) — but the menu markup + rail.js apply.
- Remove the old per-page nav/header markup AND its now-dead inline CSS block
  (`.nav`/`nav-brand`, `.topbar` link bars, `.forge-head`, the ARCHIVE-dropdown rail
  blocks `/* ═══ RITE-RAIL … */` / `/* ═══════════ RITE-RAIL …` marker blocks,
  the `.rr-drop`/`archive-menu` script + `#archive-menu` markup). Marker-splice from
  the marker comment to the next `/* ═` marker or `</style>` — dash counts vary.
- Never leave orphan `</style>`: after edits assert
  `len(re.findall(r'<style[^>]*>', src)) == len(re.findall(r'</style>', src))`.
- A CSS comment containing `*/` inside it kills the whole block — check comments.
- Buttons floor: desktop 50×40px, mobile ≤640px 44×38px (rostad's minimum — never smaller).
- Rail NEVER stacks vertically on mobile.
- `rail.js` marks the current page link `.cur`, rewires `#rr-auth` (logged in →
  "🔒 Log out" via `window.doLogout` if defined else sessionStorage cleanup;
  logged out → "⚔ Enter the Table" → login.html#gate), auto-shows `#rr-admin` when
  `sessionStorage.dnd_user` JSON has role/is_admin/admin, and exposes
  `window.railSetAdmin(bool)`.
